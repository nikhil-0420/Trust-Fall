## Reasons for Invalidation & Quarantine

This live run has been formally invalidated and quarantined due to three critical confounding flaws diagnosed in `docs/DIAGNOSIS.md`:

1. **Mock Gate Cache Hit Pollution in R1**:
   Prior mock tests and dry runs wrote prompt screening responses into `data/cache/gate/` without implementation provenance tags. When the live run executed with `USE_MOCKS=0`, `LyzrGate` read untagged cache entries generated by `MockGate` and returned them as cache hits. As a result, **0 live Lyzr API calls** were made in R1; the gate outcomes reflected mock keyword checks rather than live Lyzr detector evaluations.

2. **Sandbox Worker Process Termination Across Container Restart**:
   During the Blue defender turn (`apply_or_rollback`), `referee.sandbox.install_patch()` and `referee.sandbox.restart()` restarted the Agent37 sandbox container to apply candidate patches. Container restart killed the background `worker_band.py` process, and no process supervisor or boot hook relaunched it. As a result, the worker was completely offline during all L2 benign evaluations and throughout Round 2, causing:
   - 0/5 benign pass rate in patch validation (false rejection of valid patches).
   - 0/5 benign pass rate in Round 2.
   - 9 consecutive worker timeouts across all Round 2 attacks.

3. **Timeouts Misclassified as "Resisted" & BAND Mention Filtering**:
   Dispatcher gate-block notifications omitted Agent A from message `mentions`. Due to BAND's inbox filtering rules, Agent A was blind to these messages and suffered 20-second timeouts on every single blocked attack ticket in R1. These network/routing timeouts were misrecorded as security resists (`evidence: Worker error: timeout`, `outcome: resisted`), artificially depressing the measured Attack Success Rate (ASR) to 0.0%.
